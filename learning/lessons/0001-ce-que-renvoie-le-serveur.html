Leçon 1 · environ 15 minutes · s'appuie sur ta page d'accueil en production

Ce que renvoie le serveur quand on demande /

À la fin, tu sais dire, sur tes propres pages, quand leur HTML est fabriqué, par qui, et ce que fait ensuite le navigateur. C'est le premier point de ta mission : expliquer SSR, SSG et rendu navigateur sur tes pages.

1. Une adresse, un fichier

Analog construit les routes à partir des fichiers de src/app/pages/ qui finissent par .page.ts. Le nom du fichier devient l'adresse, et le composant doit être l'export par défaut du fichier (documentation du routage).

FichierAdresse
src/app/pages/index.page.ts/
src/app/pages/design-system.page.ts/design-system
src/app/pages/faq.page.ts (pas encore écrit)/faq

Ouvre src/app/pages/index.page.ts : la dernière ligne est export default class Home. Aucun fichier de routes à tenir à jour : c'est provideFileRouter(), dans src/app/app.config.ts, qui lit le dossier.

2. Le trajet d'une requête

  1. Le navigateur demande https://new-celeste.matthisripoche.com/.
  2. Traefik transmet la requête au serveur Node d'Analog (Nitro), dans le conteneur.
  3. Nitro cherche d'abord un fichier déjà prêt dans dist/analog/public/. S'il existe, il l'envoie tel quel.
  4. Sinon, il exécute Angular sur le serveur (src/main.server.ts) : le composant de la page produit son HTML, envoyé complet.
  5. Le navigateur affiche ce HTML tout de suite, puis télécharge le JavaScript.
  6. Angular démarre dans le navigateur (src/main.ts) et hydrate la page : il reprend le HTML déjà là au lieu de le redessiner.

Les étapes 3 et 4 sont les deux façons de fabriquer le HTML côté serveur :

Quand le HTML est fabriquéSur ton site
SSG (génération au build, ou prérendu)Une seule fois, pendant npm run build/
SSR (rendu côté serveur)À chaque requête/design-system

La surprise. Le titre de la PR #40 dit « page d'accueil rendue côté serveur ». C'est imprécis : Analog prérend / par défaut, parce qu'il lui faut un HTML pour la racine (documentation SSR d'Analog). Ton accueil est donc fabriqué une fois, au build. Il est bien produit par Angular côté serveur, mais pas à chaque visite. Tu vas le prouver toi-même.

3. L'hydratation

Le HTML reçu s'affiche, mais il est inerte : un bouton ne réagit pas tant qu'Angular n'a pas démarré. Angular réutilise le DOM rendu par le serveur au lieu de le recréer. Sans ça, la page serait jetée puis redessinée, avec un clignotement visible (guide de l'hydratation, angular.dev).

Dans src/app/app.config.ts : provideClientHydration(withEventReplay()). withEventReplay() enregistre les clics faits avant la fin de l'hydratation et les rejoue ensuite : un clic trop rapide n'est pas perdu.

4. routeMeta : le <head> de chaque page

Une page peut exporter un routeMeta à côté de son composant : titre, balises meta, gardes, redirections (documentation des métadonnées). Dans index.page.ts :

export const routeMeta = {
  title: 'Celeste Death Tracker · ton deathless, tentative par tentative',
  meta: [
    { name: 'description', content: DESCRIPTION },
    { property: 'og:title', content: 'Celeste Death Tracker' },
  ],
} satisfies RouteMeta;

Comme le HTML est fabriqué côté serveur, ces balises sont dans le HTML envoyé. C'est ce que lisent les moteurs de recherche et les aperçus de lien (Discord, réseaux sociaux), qui n'exécutent pas toujours le JavaScript.

5. À toi : prouve-le dans le terminal

Fais chaque étape avant d'ouvrir la réponse. Le but est de prédire, puis de vérifier.

Étape A : le HTML arrive-t-il complet ?

curl -s https://new-celeste.matthisripoche.com/ | grep -o "<title>[^<]*</title>"
curl -s https://new-celeste.matthisripoche.com/ | grep -c "Trois questions"
Ce que tu dois voir, et pourquoi

Le titre de routeMeta, et le texte de la page (compteur à 1). curl n'exécute aucun JavaScript : si le texte est là, c'est que le serveur l'a envoyé tout fait. Avec un site rendu dans le navigateur, comme le site actuel, tu ne verrais qu'une balise <app-root> vide.

Étape B : prérendu ou rendu à chaque requête ?

Prédis d'abord : laquelle des deux pages aura un en-tête last-modified ?

curl -sI https://new-celeste.matthisripoche.com/ | grep -iE "last-modified|etag"
curl -sI https://new-celeste.matthisripoche.com/design-system | grep -iE "last-modified|etag"
Ce que tu dois voir, et pourquoi

/ a un last-modified (l'heure du dernier build) et un etag : Nitro sert un fichier, comme un serveur de fichiers statiques. /design-system n'en a pas : son HTML vient d'être fabriqué pour ta requête.

Étape C : le fichier prérendu, en local

npm run build
ls dist/analog/public
grep -c "Ton deathless" dist/analog/public/index.html
Ce que tu dois voir, et pourquoi

index.html existe dans dist/analog/public/ et contient déjà ta page : c'est le résultat du prérendu, écrit pendant le build (ligne « Prerendering static pages… » dans la sortie). Il n'y a pas de dossier design-system/ : cette page n'est fabriquée qu'au moment de la requête.

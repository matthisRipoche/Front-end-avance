Une page en Markdown, générée au build

À la fin, ta FAQ existe sous forme de fichier HTML dans dist/, fabriqué une seule fois pendant le build à partir d'un texte en Markdown. Et tu sais dire pourquoi c'est le bon choix pour cette page.

Réponds de mémoire, sans relire la leçon 1. Chercher la réponse dans sa tête est ce qui la fixe.

1. Le chemin du texte

  1. Tu écris src/content/faq.md : un en-tête entre deux lignes --- (le frontmatter : title, description), puis le texte en Markdown.
  2. Pendant le build, le plugin de contenu d'Analog lit le fichier et sépare l'en-tête du corps.
  3. Ta page charge ce fichier et l'affiche : le corps est converti de Markdown en HTML.
  4. Le prérendu exécute ta page une fois et écrit le résultat dans dist/analog/public/faq/index.html.
  5. En production, Nitro sert ce fichier tel quel, comme pour l'accueil.

Sources : Content Routes pour le chargement et l'affichage, Static Site Generation pour le prérendu.

Pourquoi du Markdown ? Le texte de la FAQ change pour des raisons de contenu, pas de code. En Markdown, on le relit et on le corrige sans toucher à Angular. La page, elle, ne fait que charger et afficher.

3. À toi : l'exercice

Quatre TODO, dans cet ordre :

  1. faq.page.ts, TODO 1 : titre et description de la page.
  2. faq.page.ts, TODO 2 : charger src/content/faq.md.
  3. faq.page.ts, TODO 3 : afficher le titre et le corps rendu.
  4. vite.config.ts : faire générer /faq au build.

Chaque TODO dit où chercher, pas quoi écrire. Si tu bloques plus de quelques minutes, demande un indice à l'agent plutôt que la réponse.

Comment savoir que c'est fini

npm run dev      # puis http://localhost:5173/faq : la page s'affiche
npm run build
ls dist/analog/public                          # un dossier faq/ ?
grep -c "<h2" dist/analog/public/faq/index.html  # 8 questions
Et si l'accueil disparaît de dist/ ?

Relis la section « surprise » de la leçon 1 : pourquoi l'accueil était-il prérendu sans que tu le demandes ?

Une question ? Pose-la à l'agent, avant, pendant ou après l'exercice. Quand tu as fini, dis-le : il relira ton code et t'expliquera ce qui ne va pas, sans le corriger à ta place.
